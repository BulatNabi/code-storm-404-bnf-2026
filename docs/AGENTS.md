# Финтех-регуляторный радар

## Описание проекта

Ассистент для продуктовых и инженерных команд финтеха: принимает описание фичи (user story или свободный текст) и в реальном времени определяет потенциальные регуляторные риски (AML, KYC, GDPR, PSD2/PSD3, AI Act, MiCA, DORA и др.), формирует чеклист действий для PO/Compliance/Engineering и список документов к обновлению.

**Хакатон:** Финтех по финансовому сектору (Узбекский рынок), Дорожка 4, 48 часов.

**Ключевая ценность:**
- Детекция неочевидных регуляторных рисков на этапе планирования фичи, а не после релиза
- Конкретные ссылки на статьи законов (не галлюцинации — RAG по верифицированному корпусу)
- Чеклист разбит по ролям: Product Owner / Compliance Officer / Engineering Lead
- Интерфейс понятен нетехническим специалистам

---

## Структура репозитория

Проект состоит из трёх независимых микросервисов, каждый в своей папке:

```
/
├── docs/       — общая документация: ресерч, ТЗ, user stories
├── frontend/   — веб-интерфейс пользователя
├── backend/    — API-сервер, оркестрация, бизнес-логика
└── ai-core/    — AI-сервис: RAG, LLM-вызовы, knowledge base
```

Каждый сервис разрабатывается и деплоится независимо. Взаимодействие — через HTTP API (REST + Server-Sent Events для стриминга).

## Архитектура

```
[Пользователь (браузер)]
        │
        ▼
[Frontend — Node.js :3000]
        │  HTTP REST + SSE
        ▼
[Backend — FastAPI :8000]
        │  HTTP REST
        ▼
[AI-сервис — FastAPI :8001]
```

**Поток данных:**
1. Пользователь вводит описание фичи во Frontend
2. Frontend отправляет запрос на Backend
3. Backend проксирует запрос в AI-сервис и стримит ответ обратно через SSE
4. Frontend рендерит результат по блокам по мере поступления

## Микросервис: Backend (`/backend`)

**Порт:** 8000  
**Стек:** Python 3.11+, FastAPI, SQLite

### Ответственность
- Приём запросов от Frontend
- Валидация входных данных
- Проксирование запросов в AI-сервис
- SSE-стриминг ответа AI-сервиса во Frontend
- Сохранение истории запросов в SQLite
- Интеграция с Jira: создание задач по результатам анализа (опционально)

### Jira-интеграция
- Кнопка «Создать задачи в Jira» на фронте отправляет запрос в Backend
- Backend создаёт Epic «Compliance review: [имя фичи]» и Stories по каждому пункту чеклиста, разделённые по ролям (PO / Compliance / Engineering)
- Транспорт: Jira REST API v3 (`/rest/api/3/issue`), авторизация через API Token
- В описании каждой задачи — цитата из закона и ссылка на источник

### Соглашения
- Язык: Python, `snake_case`
- Типизация: Pydantic v2 для всех схем
- `Optional[T]` и `List[T]` из `typing` (Python 3.9 совместимость)
- Все эндпоинты документированы через FastAPI OpenAPI (`/docs`)
- Аутентификация: не нужна для MVP

## Соглашения для агентов (общие)

- Работай только в папке своего сервиса (`/frontend`, `/backend`, `/ai-core`)
- Не изменяй код других сервисов — только API-контракты согласуются совместно
- Все межсервисные запросы идут через HTTP, не через прямой импорт
- Docker Compose в корне запускает все три сервиса одной командой
- `.env` файлы — в каждом сервисе свой, не коммитить в репозиторий
- Логи: структурированные JSON-логи для всех сервисов
