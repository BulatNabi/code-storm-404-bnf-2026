# RegTech AI Assistant 🏦

Репозиторий представляет собой интеллектуальную систему (`ai-core`), предназначенную для помощи продуктовым, инженерным и комплаенс-командам в финтех-отрасли. Основная задача — анализ продуктовых инициатив и нормативно-правовых актов (НАП) с помощью больших языковых моделей (LLM) для выявления регуляторных рисков, формирования чек-листов и динамического извлечения правил.

---

## 🎯 Основные возможности

Система разделена на два ключевых модуля (доступны через CLI и UI):

### 1. Feature Assistant (Анализ продуктовых фич)
На входе получает текстовое описание новой функциональности (например, "добавляем перевод по номеру телефона").
На выходе мгновенно предоставляет:
- Затронутые **регуляторные домены** (AML, защита ПДн, лицензирование и т.д.).
- Оценку уровня риска (`low`, `medium`, `high`).
- **Что именно нужно проверить** (чек-лист комплаенса).
- **Какие документы и процессы** необходимо обновить.
- Список уточняющих вопросов и "красных флагов".

### 2. Rule Generator (Извлечение правил из НАП)
На входе получает нормативно-правовой акт или внутренний регламент в формате Markdown.
На выходе формирует базу:
- **Атомарных правил**, которые можно автоматически проверять.
- Каждое правило содержит методы проверки, позитивные и негативные примеры.
- 🔄 **Динамическое расширение таксономии:** если LLM обнаруживает требование, под которое нет подходящего тега в базе, она придумывает новый тег, описывает его и автоматически сохраняет в `tags.json`.

## 🏗 Архитектура

Система имеет модульную архитектуру, разбитую на смысловые блоки:

### Компоненты системы
- **`agents/`** — Модули и агенты для автоматизированного выполнения задач (зарезервировано для новых AI-агентов).
- **`core/`** — Основные вычислительные пайплайны:
  - `chunker/` — парсинг и интеллектуальное разбиение текстов.
  - `classifier/` — ML-классификация.
  - `converter/` — конвертация документов (например, Docling).
  - `rules_generator/` — генерация правил (Map-Reduce стратегия для длинных текстов).
  - `validation/` — валидация данных и требований.
- **`domain/`** — Бизнес-логика:
  - `fintech_rules/` — специфичные правила и логика для финтех-отрасли.
- **`shared/`** — Общие утилиты и схемы:
  - `common/client/llm_client.py` — Адаптер для работы с LLM (Yandex Qwen / OpenAI).
  - `common/tags_loader.py` — Единый менеджер таксономии (загружает и динамически сохраняет теги).
  - `schema/` — JSON-схемы и локальная БД.
- **`interfaces/`** — Точки входа в систему (UI и CLI скрипты):
  - `app.py` — Streamlit веб-интерфейс.
  - `feature_assistant.py` — Ядро анализа продуктовых фич.
  - `run_feature_analysis.py` и `run_parser.py` — CLI скрипты запуска.

### База данных (Таксономия)
В качестве базы данных выступает локальный JSON-файл:
- **`shared/schema/tags.json`** — Содержит словарь всех известных системе тегов (доменов). Каждый объект включает:
  - `tag_name` — уникальный идентификатор (например, `aml_cft`).
  - `category` — категория (technical, functional, data, compliance).
  - `description` — подробное описание того, что относится к этому тегу.
  
*Пример записи в БД:*
```json
{
  "tag_name": "data_protection",
  "category": "compliance",
  "description": "Сбор и обработка персональных данных, согласия, локализация..."
}
```

## 🧠 Используемые модели (LLM)

По умолчанию проект настроен на работу с моделями **Yandex Cloud**.
Конфигурация модели задана в файле `ai-core/shared/common/client/llm_client.py`.

Текущая модель: `gpt://{folder}/aliceai-llm/latest`

### Как поменять модель на OpenAI (GPT-4o)?
1. Откройте файл `shared/common/client/llm_client.py`.
2. В методе `__init__` закомментируйте строку `base_url`:
   ```python
   self._client = AsyncOpenAI(
       api_key=api_key,
       # base_url="https://llm.api.cloud.yandex.net/v1",
       timeout=300.0,
   )
   ```
3. В методе `request` измените имя модели:
   ```python
   model_name = "gpt-4o"
   ```

## 🚀 Запуск и использование

### Требования
- Python 3.9+
- Установленные зависимости из `requirements.txt`
- Наличие файла `.env` в корне проекта со следующими переменными:
  ```env
  YANDEX_CLOUD_API_KEY=ваш_api_ключ
  YANDEX_CLOUD_FOLDER=ваш_id_каталога
  ```

### Установка зависимостей
```bash
cd ai-core
pip install -r requirements.txt
```

### 1. Запуск через UI (Рекомендуется)
```bash
python -m streamlit run interfaces/app.py
```
Откроется дашборд в браузере с двумя вкладками: Анализ фич и Генерация правил.

### 2. Запуск через CLI (Анализ фичи)
С использованием LLM:
```bash
python interfaces/run_feature_analysis.py --text "Описание вашей фичи"
```
Без LLM (эвристика):
```bash
python interfaces/run_feature_analysis.py --text "Описание вашей фичи" --no-llm
```

### 3. Запуск через CLI (Генерация правил из Markdown)
```bash
python core/rules_generator/cli.py --input path/to/document.md
```
Результат будет сохранен в папку `generated_rules/`.
