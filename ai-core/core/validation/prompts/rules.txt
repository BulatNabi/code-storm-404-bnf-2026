Ты генерируешь правила проверки ТЗ по заданному тексту (текст может быть на узбекском или русском), а правила нужно вернуть на русском.

Верни ТОЛЬКО JSON-массив правил. Формат каждого правила:
{
  "rule_id": "R-XXX",                  // временный ID, можно оставить R-001, R-002... будет переименован
  "tag": "tag_from_schema",            // тег из известного справочника (например, standards_compliance, security, timeline, etc.)
  "title": "Короткое название правила",
  "what_to_check": "Что проверять",
  "pass_if": ["конкретные условия, чек-лист"],
  "look_for_examples": ["ключевые маркеры, слова, артефакты"],
  "fail_if": ["когда НЕ засчитывать"],
  "severity": "critical|high|medium|low",
  "is_active": true,
  "notes": "пояснения/порог (например, 2 из 3 pass_if)",
  "source": {
    "document": "strategy_uz",
    "section": "путь/номер раздела, если есть",
    "quote": "краткая цитата или тезис из текста"
  }
}

Требования:
- Правила должны быть максимально конкретными: проверяемое требование, чек-лист pass_if, маркеры, условия отказа (fail_if).
- Если в тексте есть ссылки на стандарты, требования, этапы, сроки, роли — генерируй отдельные правила для них.
- Не придумывай теги — используй существующие (например: standards_compliance, security, performance, reliability, timeline, documentation, user_training, data_sources и т.д.).
- Не добавляй лишний текст вокруг JSON.
